# 投稿モチベーション・貢献実績機能（仕様の要約と方針）

> 受領: 2026-11-25。**方針A（端末の記録）で実装済み**（投稿完了パネル・/me・report_views・称号）。ポイント・クーポンは**実装しない**（`docs/FUTURE_VISION.md` の将来構想）。今回は「役に立った」を実感できる仕組みだけを作る。

## 仕様の要点
1. **投稿完了の画面**：「投稿ありがとうございます！」「あなたの情報がイベント参加者に共有されました。」＋投稿内容・日時・イベント名。完了後すぐイベントページに反映され、自分の投稿を確認できる。
2. **貢献実績**：累計投稿数／情報提供したイベント数／駐車場・トイレ・シャトルバスそれぞれの投稿数／自分の投稿の累計閲覧数（実データがあるときだけ）。投稿履歴（イベント名・内容・日時・現在の状態）。
3. **称号・バッジ**：情報提供サポーター／イベント情報サポーター／駐車場情報サポーター／トイレ情報サポーター／シャトルバス情報サポーター／イベナウ貢献メンバー など。ランキングや競争要素は作らない。重複・不正投稿は実績に数えない。
4. **閲覧数**：「あなたの投稿は現在328回閲覧されています」。実際の閲覧だけを数え、同じ人の短時間の連続閲覧は除外。少ないうちは表示しない。「役に立った人数」など根拠のない数字は出さない。
5. **登録**：閲覧はログイン不要。投稿もできるだけ簡単に。実績を残すには利用者を識別する仕組みが必要。登録を求めるなら投稿の妨げにならないタイミングで。匿名投稿はイベント情報の更新には使うが、個人の実績には紐付けないのが基本。
6. **将来の拡張**：有効な投稿へのポイント、全国共通ポイント、履歴、協賛クーポン（上限・期限・回数管理）を後から足せる構造。**イベナウは費用を負担しない。**

## 実装方針（案）
- **識別**：今ある「ブラウザごとの匿名ID（Cookie）」を使い、登録なしで「この端末での記録」として実績を表示する。
  ログイン（アカウント）は、ポイント導入時か、利用者から「機種変更しても残したい」という需要が出た時点で追加し、
  そのときに端末の記録をアカウントへ引き継ぐ。
- **有効な投稿**：非表示・通報済みの投稿は数えない。同じ地点への短時間の重複は既存の連投制限で防止済み。
- **閲覧数**：イベントページで「現在の状況」として実際に表示された投稿を、閲覧者ごと（匿名ID）に30分に1回まで記録する。
  自分自身の閲覧は除外し、10回未満は表示しない。
- **称号**：有効な投稿の件数・カテゴリから計算で決める（保存しない）。
- **追加するもの**：投稿完了パネル／マイページ（`/me`）／閲覧記録の表（`report_views`）。ポイント・クーポン関連の表は作らない。

## 追記（2026-11）
- 飲食・屋台を扱わない方針に合わせ、「飲食エリア情報サポーター」を「シャトルバス情報サポーター」に置き換えた（実績の数もシャトルバスに）。
- 前に投稿したイベントのページを開くと「このイベントでのあなたの投稿が、これまで○回見られました」を本人にだけ表示（10回以上・実データのみ・サンプルでは出さない・タップで /me）。

## 見た人の数（2026-11 更新）
- 投稿が**その地点の最新の投稿として表示されている間だけ**、イベントページを見た人を数える（次の投稿で入れ替わったら止まる・表示期限は90分）。
- **同じ人は1回だけ**（ブラウザの匿名ID、無ければIPのハッシュ）。本人と検索ロボットは数えない。単位は「人」（以前の「回」から変更）。
- 実績ページの履歴に投稿ごとの「○人が見ました」、合計は「のべ○人」。実データのみ・ランキングは作らない。
