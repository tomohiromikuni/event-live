# SNS自動投稿（X）実装計画

仕様書「イベナウ SNS自動投稿機能 開発仕様書」に対する計画。**まだ実装していない**（第1段階から順に進める）。

## 方針
- 投稿文は**テンプレート（AIなし）**で作る：実際の投稿データ以外が入らない・費用0円・毎回同じ品質。
- SNSごとの処理は `lib/sns/` に分ける（`x.ts` が `post(text)` を実装。Threads 等はファイルを足すだけ）。
- 最初は「確認モード ON」：自動で作るのは**下書き**まで。管理画面で確認 →「投稿する」。

## 投稿の種類と条件
| 種類 | タイミング | 条件 |
|---|---|---|
| 前日案内 | 前日 18時ごろ | 公開中・実イベント・開催予定。1イベント1回 |
| 当日案内 | 当日 7時ごろ | 同上。1イベント1回 |
| 現地の混雑 | 開催中、15分ごとに判定 | 直近30分の投稿が2人以上から。前回の投稿から60分以上・内容に変化あり。1イベント1日3回まで |
| 状況の変化 | 同上 | 同じ分類で「空きあり→満車」など段階が2つ以上変わった |
| 中止・延期 | 管理画面で開催状況を変えたとき | **必ず確認モード**（下書きのみ） |

- 時刻は「14:35時点の投稿」と必ず書く。30分より古い投稿は使わない。件数（直近30分で○件）を書く。
- 「※来場者の投稿です（公式発表ではありません）」を必ず付ける。
- 同じ内容は二重に投稿しない（イベント・種類・日付・内容から作る重複キー）。
- 全体の上限：1日の最大投稿数・最低間隔（管理画面で設定）。

## DB（追加のみ）
- `sns_posts`：id, event_id, channel(x), kind(pre/today/live/change/status), text, dedupe_key(UNIQUE), status(draft/queued/posted/failed/canceled/skipped),
  scheduled_at, posted_at, external_id, external_url, error, attempts, snapshot(JSON：使った投稿の時刻・件数), created_at
- 設定は既存の `app_settings`（sns_enabled, sns_review_mode, sns_kinds, sns_daily_max, sns_min_interval_min, sns_live_min_reports, sns_min_views）

## 実行
GitHub Actions（既存の自動収集と同じ仕組み）で15分ごとに `POST /api/cron/sns` を呼ぶ。投稿の判定はDBだけで行い、Xに送るのは投稿するときだけ。

## X の準備
- X Developer Portal でアプリを作成（権限 Read and Write）→ API Key / Secret、Access Token / Secret（OAuth 1.0a）
- Vercel の環境変数：`X_API_KEY` `X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_SECRET`（コードには書かない）
- 料金は従量課金のクレジットを少額購入。X のプロフィールに「自動化されたアカウント」のラベルを設定。
