# EVENOW（イベナウ）設計書（MVP）

## 1. 企画の整理

| 観点 | 内容 |
|---|---|
| 価値 | 「行く前」＝全国イベントの検索・基本情報／「当日」＝会場マップ＋来場者のリアルタイム投稿 |
| 差別化 | 地点単位（トイレ①、臨時駐車場…）でワンタップ投稿し、鮮度つきで地図に反映（Waze型） |
| 前提 | 主催者と契約しない第三者サービス・無料・ログイン不要・スマホブラウザ最優先 |
| スケール | 数千〜数万イベントを共通DB＋共通テンプレートで生成（イベント別サイトは作らない） |

## 2. 機能一覧

| 区分 | 機能 | MVP |
|---|---|---|
| 探す | キーワード検索／今日・今週末・今後／ジャンル／都道府県／開催日／注目／盛り上がり中 | ✅ |
| 詳細 | 基本情報（取得できない項目は「情報なし」）・ジャンル別表示項目・開催状況（中止/延期）・情報元URLと確認日・サンプル表示 | ✅ |
| マップ | ベース地図＋独自デザインの地点マーカー、カテゴリ絞り込み、拡大縮小、地点選択 | ✅ |
| 投稿 | 地点を選んでワンタップ投稿、匿名、投稿時刻記録、鮮度表示、20秒ごと自動更新 | ✅ |
| 不正対策 | 同一地点3分間隔、10分10件/ブラウザ、10分40件/IPハッシュ、通報（3件で自動非表示）、管理者削除 | ✅ |
| 管理 | イベントCRUD、地点のマップ編集（クリック追加・ドラッグ移動）、投稿・通報管理、ジャンル/カテゴリ/選択肢設定 | ✅ |
| 将来 | 自動収集パイプライン、管理者アカウント、画像アップロード、全文検索、SSE/WebSocket、PWA、広告 | – |

## 3. 技術構成

| レイヤ | プロトタイプ | 本番想定 | 理由 |
|---|---|---|---|
| フレームワーク | Next.js 15 (App Router, TypeScript) | 同じ | SSRでSEO（イベントページ数万件）＋APIを1つに集約、保守者が多い |
| DB | PostgreSQL（ローカルは組込みの PGlite、`DATABASE_URL` 指定時は Neon / Supabase 等） | 同じ（Vercel + Neon） | サーバーレスでもデータが永続。将来 PostGIS・pg_trgm で地理/全文検索 |
| 会場マップ | 簡易マップ（見取り図）。Leaflet の CRS.Simple で白い用紙にエリア・線・施設を描画 | 同じ | 外部の地図データ不要（利用条件・費用なし）。拡大縮小・タップは地図と同じ操作 |
| リアルタイム | 20秒ポーリング | ポーリング＋CDN短期キャッシュ → 必要に応じ SSE / Supabase Realtime | 来場者数のピークでも安定・安価 |
| ホスティング | Vercel（GitHub 連携で自動デプロイ） | 同じ | 無料枠から開始、規模に応じて有料プラン |
| 管理認証 | 共有パスワード＋署名Cookie | Supabase Auth / Auth.js ＋ロール | |

## 4. データベース設計

```
genres ──< genre_categories >── spot_categories >── report_types
  │                                   ▲  (選択肢JSON: value/label/level)
  │                                   │
events ──< event_categories >─────────┘   ※行があればジャンル既定を上書き
  │
  ├──< spots (category_id, lat, lng)
  │        │
  └──< reports (spot_id, value, label, level, client_id, ip_hash, created_at, hidden, flag_count)
                 │
                 └──< report_flags (client_id UNIQUE per report, reason, resolved)
```

- **ジャンル差の吸収**: 「ジャンル → 既定カテゴリ」「カテゴリ → 投稿選択肢セット」「イベント → 個別上書き」の3段で、コード変更なしに管理画面から設定。
- **表示項目の差**: `genres.info_fields` で詳細ページの項目と順序を指定、`events.extra_info` でジャンル固有項目（打ち上げ数・出演者等）。
- **投稿**: `label` を投稿時にスナップショット保存（選択肢変更後も履歴が壊れない）。`level` 0〜4 で色分け。
- **出典管理**: `source_url` / `source_checked_at` / `is_sample`。
- インデックス: events(start_date,end_date)/(prefecture)/(genre_id)、reports(event_id,created_at)/(spot_id,created_at)/(client_id,created_at)。

## 5. 鮮度ルール（`lib/freshness.ts`）

| 経過 | 表示 |
|---|---|
| 30分未満 | 最新情報（「5分前」） |
| 30〜90分 | 「45分前の情報」＋薄色・点線マーカー（古い可能性を明示） |
| 90分以上 | 現在の状況に反映しない →「現在の情報はありません」 |

投稿は開催期間中のみ受付（中止・延期イベントは不可）。

## 6. ページ構成・画面遷移

```
/ (トップ) ──検索/チップ──> /search?q&genre&pref&when&date ──> /events/[slug]
                                                            ├ #live  地図＋地点リスト＋ボトムシート(ワンタップ投稿)＋投稿フィード
                                                            └ #info  基本情報・情報元
/admin-login → /admin (イベント一覧)
                 ├ /admin/events/new
                 ├ /admin/events/[id]  地点マップ編集＋イベント編集＋削除
                 ├ /admin/reports(?flagged=1|event=ID)  非表示/再表示/削除/問題なし
                 └ /admin/settings  ジャンル・カテゴリ・選択肢セット
API: GET /api/events/[id]/live, POST /api/reports, POST /api/reports/[id]/flag
```

## 7. 自動収集（次フェーズの設計方針）

1. 収集元レジストリ（URL・利用規約確認日・許可状態）を管理し、**許可されたソース/API/オープンデータのみ**取得（robots.txt 遵守）。
2. 取得HTML → LLMでイベント名・日付・場所・時間・ジャンルを構造化抽出（JSONスキーマ指定）→ ジオコーディング。
3. `event_candidates` ステージングテーブルに保存（情報元URL・取得日時付き）→ 管理画面で確認・修正して公開。
4. 開催日・中止情報など誤りが問題になる項目は必ず人の確認を通す。

## 8. 検索エンジン対策（SEO）と記事の自動生成

### 実装済み（土台）
- `sitemap.xml`（公開中の実イベントのみ。サンプル・非公開は除外）／`robots.txt`（管理画面・APIは除外）
- イベントページごとのタイトル・説明文・canonical・OGP（SNS共有時の表示）。`lib/seo.ts`
  - タイトル：「イベント名＋年 駐車場・（公式情報があれば）シャトルバス・トイレ・交通規制と混雑状況」
  - 説明文：日程・会場・駐車場/シャトルバスの公式情報の冒頭（事実のみ）
- 構造化データ：Event＋BreadcrumbList（パンくず）
- URL：`/events/{英小文字のID}`（例 `sumida-hanabi`。年は入れず毎年同じURL）。自動の `ev-xxxx` のままなら管理画面に案内が出る。
  URLを変えると古いURLは `slug_redirects` に残り、308 で新しいURLへ転送（`?ref=` も引き継ぐ。何度変えても最新へ）。
- 内部リンク：詳細ページ下部に「ほかのイベント（同じ都道府県→同じジャンル・開催中/これから・最大4件）」
- 構造化データ `schema.org/Event`（Google 検索の「イベント」枠に載るための形式。開催状況＝中止/延期も反映）
- サンプル（架空）イベントは `noindex` にして検索結果に出さない
- 公開URLは `NEXT_PUBLIC_SITE_URL`（未設定なら Vercel の本番URL）

### 将来：記事の自動生成（設計方針）
検索流入を増やすため、DBのイベント情報から「読み物ページ」を自動で作る。

| 記事の種類 | 例 | 生成元 |
|---|---|---|
| まとめ記事 | 「今週末の東京都のイベント」「12月の花火大会まとめ」 | 検索条件（期間×地域×ジャンル）で自動作成。AI不要・常に最新 |
| イベント攻略記事 | 「○○花火大会 混雑回避ガイド（トイレ・駐車場・おすすめ到着時間）」 | イベント情報＋過去の投稿データの集計をAIで文章化 |
| 開催後レポート | 「○○フェス 当日の混雑の推移」 | 当日の投稿を時間帯別に集計してグラフ化＋AI要約 |

- 処理の流れ: 定期実行（Vercel Cron）→ 記事の下書きを `articles` テーブルに保存 → **管理画面で確認してから公開**（誤情報・推測の混入を防ぐ）。
- 記事にはデータの根拠（集計期間・投稿件数・情報元URL）を必ず併記し、推測で事実を補わない。
- 同じ内容の薄いページを量産しない（検索エンジンの評価が下がるため）。投稿件数などの閾値を満たしたものだけ生成する。
- 先に「まとめ記事」（低コスト・誤情報リスク小）→ 実データが貯まったら「攻略記事」「レポート」の順に導入する。

## 9. 会場マップ（簡易マップ・見取り図）

- 実際の地図（緯度経度）は使わず、運営のガイドマップを参考に描き起こした**見取り図**を表示する。利用者の位置情報は使わない。
- 座標系: 横幅1000を基準にした用紙（縦はガイドマップの比率）。`events.map_w / map_h`、施設 `spots.lat/lng` とエリア・線 `map_shapes.coords` は用紙上の [y, x]。
- 作図（管理画面）: ガイドマップ画像を**ブラウザ内だけ**で下敷き表示（サーバーへ送信・保存しない）→「施設を置く」「エリアを描く」「線を描く」の3つで描く。
- 権利面: 描けるのは四角・多角形・線・施設アイコンのみ、色は EVENOW の固定色（`lib/shapes.ts`）。ガイドマップの絵・配色は再現しない。
- 旧方式（実地図上の座標）のデータは v3 マイグレーションで見取り図の座標に自動変換される。
- **地図モード（map_mode = geo）**: Google マイマップ等の緯度経度データから取り込んだイベントは、座標をそのまま保存し、
  背景に国土地理院の淡色地図（地理院タイル・出典表示あり）を表示する。会場が街全体に広がるイベント（駐車場が離れている等）向け。
  どちらのモードになるかは取り込み方で自動的に決まる（ガイドマップから描く＝見取り図、マイマップから取り込む＝地図）。

## 10. かんたん表示（会場マップなし）

- `events.map_mode = 'simple'`：地図を出さず、ジャンルに応じた決まった項目（`spots.generic = 1`）の一覧で状況を共有する。
  項目：会場・入口／（花火）観覧場所／（音楽・アニメ）物販・グッズ／駐車場（周辺）／（シャトルバスの公式情報があるとき）シャトルバス／トイレ／飲食・屋台／周辺の道路。
  あとからシャトルバスの情報を入れて保存すると、項目が自動で足される。
- 投稿は通常と同じ選択式ワンタップ。自由文は受け付けない。
- 公開の条件：開催場所（会場名か住所）と、公式サイトまたは情報元URL。
- 自動収集の候補を承認したとき、公式マイマップのリンクがなければ自動でかんたん表示にする。
- 管理画面で施設・エリアを描く／マップを取り込むと、自動で通常表示に切り替わり、かんたん表示の項目（とその投稿）は削除される。

## 11. 詳細ページ（カード形式・2026-11）

- 上から：イベント名・日時・場所 →「○○の駐車場・シャトルバス・トイレ（現地の状況）」→ カード → 会場マップ（あるときだけ）→ 開催概要・共有・非公式の注記・関連イベント。
- **カードは 駐車場・シャトルバス・トイレ・飲食 の4つ**（`components/EventLive.tsx` の TOPICS）。1カードに「いまの状況（来場者の投稿）」「公式情報（空なら未確認）」「投稿ボタン」をまとめる。
  - 交通規制はカードにせず、公式情報があるときだけ駐車場カードの中に1行。
  - シャトルバス・飲食は、地点か公式情報があるときだけ出す。駐車場・トイレは常に出す。
  - 場所が複数あれば1か所1行（投稿がある所を新しい順に3つまで、残りは「ほかの○か所」に畳む）。
- 会場マップがあるイベントは、カードの下の地図でも地点をタップして投稿できる（同じシート）。
- 「最新の投稿」一覧は廃止。通報は、地点のシートの「この場所への最近の投稿」から行う。
- かんたん表示の項目は 駐車場・（シャトルバス）・トイレ・飲食 に変更。以前の項目（会場・入口・観覧場所・物販・周辺の道路）は既存イベントでは削除せず、画面に出さないだけ。
- ページ上部に閲覧人数（今日○人・これまでのべ○人。のべ10人未満・サンプルは出さない）。
